# Smart Effect Camera App — Technical Planning

## 1. Product Overview

A cross-platform camera application for **iOS and Android** that allows users to:

* Take photos using the device camera
* Select ready-made templates/effects before taking a photo
* Apply visual effects and overlays
* Save photos to the device
* Share photos to social media
* Download additional templates/effects
* Support premium features in the future

The initial product should focus on **simple, reliable camera effects** rather than complex AR/3D functionality.

# 3. React Native vs Expo

## React Native

React Native is the core cross-platform mobile framework.

It allows developers to build:

```text
TypeScript / JavaScript
        ↓
React Native
        ↓
iOS + Android
```

React Native can also access native functionality through:

* Swift
* Objective-C
* Kotlin
* Java
* Native modules

This gives developers a high level of control.

---

## Expo + React Native

Expo is a development platform and toolchain built around React Native.

It provides additional tools and libraries such as:

* Expo Camera
* Expo Image
* Expo SQLite
* Expo Notifications
* Expo Router
* Expo File System
* EAS Build

Instead of manually configuring many native development components, Expo can simplify the development process.

### Important

Expo does **not** mean the application is limited to simple apps.

When required, the project can still use:

* React Native libraries
* Expo modules
* Custom native modules
* Swift
* Kotlin
* Native iOS/Android functionality

Therefore:

> **Expo + React Native is the recommended starting point for this project.**

---

# 4. Why Use Expo + React Native?

The application is intended for both:

* iOS
* Android

Using React Native allows most of the application code to be shared.

Example:

```text
                 TypeScript
                     │
              React Native
                     │
          ┌──────────┴──────────┐
          ↓                     ↓
        iOS                   Android
```

Expo additionally reduces initial setup complexity.

This is particularly useful for MVP development.

# 6. Camera Features

## MVP Camera Features

The first version should support:

* Front camera
* Rear camera
* Flash
* Camera preview
* Photo capture
* Basic zoom
* Image preview
* Retake
* Save to device
* Share image

Avoid implementing advanced manual camera controls initially.

For example, do not initially expose:

* ISO
* Shutter speed
* White balance
* Focus distance
* Exposure compensation

The goal is to make the application simple:

> **Select an effect → point camera → take photo.**

# 8. Types of Effects

Effects can be divided into several levels.

## Level 1 — Static Overlay

The easiest type.

Example:

```text
Camera Photo
      +
PNG overlay
      ↓
Final Photo
```

Examples:

* Birthday frames
* Flower frames
* Christmas frames
* Halloween frames
* Cute decorations
* Sparkles
* Text decorations

This should be part of the MVP.

---

## Level 2 — Image Filters

Modify the appearance of the captured image.

Examples:

* Brightness
* Contrast
* Saturation
* Warm tone
* Cool tone
* Vintage
* Black and white
* Film effects

Example:

```text
Original
   ↓
Filter
   ↓
Processed Image
```

---

## Level 3 — Face Detection Effects

The application detects parts of a person's face.

For example:

```text
          Face
           │
    ┌──────┼──────┐
    ↓      ↓      ↓
  Eyes    Nose   Mouth
```

This allows effects such as:

* Virtual glasses
* Animal ears
* Hats
* Makeup effects
* Face decorations

The effect can follow the user's face.

---

# 9. What Is AR?

AR means **Augmented Reality**.

AR places virtual content into the real-world camera view.

For example:

```text
Real camera
     +
Virtual object
     ↓
AR scene
```

A virtual object can remain attached to a person's face or a location in the environment.

Example:

```text
        👤
       😎
        ↑
Virtual glasses
```

When the user moves their head, the glasses move with the face.

---

# 10. What Is 3D?

A 3D effect uses a three-dimensional model instead of a flat image.

Example:

```text
        🐰
      3D Model
         │
         ↓
Camera Scene
```

The user may be able to view different sides of the object.

Possible future features:

* 3D characters
* Virtual pets
* 3D decorations
* Virtual furniture
* 3D masks
* Interactive objects

---

# 11. AR / 3D Is Not Required for MVP

The first version should **not depend on AR or 3D**.

Start with:

```text
Camera
   ↓
Template
   ↓
Photo
   ↓
Overlay / Filter
   ↓
Save
```

This reduces:

* Development time
* Native complexity
* Device compatibility issues
* Performance problems
* Testing requirements

AR and 3D can be introduced later if they provide real product value.

# 19. Performance Considerations

Camera applications are more performance-sensitive than normal CRUD applications.

Important areas:

### Memory

Large images can consume significant memory.

Avoid loading multiple full-resolution images simultaneously.

### GPU

Real-time filters and AR effects may require GPU processing.

### Battery

Continuous camera processing can consume significant battery.

### FPS

Real-time effects should maintain a smooth preview.

Target:

```text
30 FPS minimum
60 FPS where practical
```

### Device compatibility

Test on:

* Low-end Android
* Mid-range Android
* High-end Android
* Older iPhone
* Recent iPhone
